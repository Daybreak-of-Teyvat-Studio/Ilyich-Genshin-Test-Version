### 新增方法（已写入技能 `hoi4-mod-bug-triage`）
1. **"假乱码"排除法**：控制台按 GBK 显示 UTF-8 会伪造乱码假象 → 只认字节（`b.count(b'\xef\xbf\xbd')`），复核用 `unicode_escape` 输出。
2. **乱码指纹**：2 字节产物落 `U+0080–U+07FF`、3 字节落 `U+0800–U+FFFF`（随机汉字/谚文）、4 字节落平面 14–16。⚠️ **`U+FFFD` 本身落在 3 字节区，最容易漏判**。
3. **`§`(U+00A7) 必须白名单**，否则会毁掉本地化颜色码。
4. **「首乱码~末乱码」整段删除法**：区间内夹的 ASCII 是中文 GBK 字节残渣（一起删），区间外的前后缀是作者手写 ASCII（要留）——所以 `# --- 1. <乱码> ---` 能保住 `# --- 1. ---`。
5. **汉字守恒审计**：difflib 对齐后做 `set(旧汉字)-set(新汉字)` 差集，逐条确认"丢失的汉字"都来自被删的乱码行。⚠️ difflib 的 `delete` 计数会并入相邻 replace 而偏小 → 删行数必须用 `len(前)-len(后)`，否则会报假的 CRLF 校验失败。

## batch32：把 DOT_nuke_on_actions.txt 被注释的 `limit` 还原成真实修复

**用户诉求**：「我仅仅希望你处理这部分的内容」——只处理 `common/on_actions/DOT_nuke_on_actions.txt`
第 106–109 行那段被 `# [注销]` 掉的 `limit` 块；先问过「是不是把 limit 改成 if 就好了」。

### 结论：不能简单改名，要重构
1. `limit = {…}` 里装的是**触发器**，`if = { limit = {…} …效果… }` 里键名**仍然叫 `limit`** ——
   只是把它套进 `if`；直接改名会让引擎把 `has_global_flag` 当效果解析。
2. **收尾 `}` 位置要搬**：`if` 必须包住其后**整段效果**（原 L110–L191），所以原 L109 的 `}` 删掉，
   在 L191 之后补一个 `}`。
3. **原写法本身还有作用域错**：`From = { is_ai = yes }` —— 手册（`manual_keys_detail.json`）证实
   `is_ai` 是**国家作用域**触发器，而 `on_nuke_drop` 的 `FROM` 是**被炸的州**（原版 `00_on_actions.txt:384`
   与手册 on_actions 表都写明；`is_core_of` / `controller` / `remove_building` 全是州作用域）。
   → 改成 `owner = { is_ai = yes }`（手册：`owner` 可用在 state 作用域）。
