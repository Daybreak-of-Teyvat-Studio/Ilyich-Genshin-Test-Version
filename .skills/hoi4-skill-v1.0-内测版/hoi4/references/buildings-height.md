# 建筑高程与防穿模（map/buildings.txt 第 4 列 y）

> **本模块由绿豆糕制作**——高程公式、行序判据与防穿模方法均来自绿豆糕的工作，脚本为其工具的整理与扩展。

**读这份的场景**：建筑模型悬空/浮空/陷进地里；heightmap 改过之后建筑不贴地；建筑被山体遮挡穿模；要按新地形重算建筑高度。

## 症状判别（先分清三件事）

| 现象 | 归属 | 文件 |
|---|---|---|
| 建筑浮空/入地，水平位置没错 | 高程过期（见 §1） | `buildings.txt` 第 4 列 |
| 贴地了但模型边缘/半截被山体埋住 | 穿模（见 §2） | 同上 |
| 胜利点/旗帜图标浮在海面 | `positions.txt` 坐标落海，另一套修法 | `map/positions.txt` |
| 图上是占位方块、`mapobject_N failed to load` | `trees.bmp` 用了没有 mesh 的索引 | `map/trees.bmp` |
| 日志 `Building xxx doesn't have an entity` | 实体定义缺失，建筑**不显示**而非浮空 | `gfx/entities/*.asset` |

## §1 高程重算（heightmap 变了必做）

格式 `州id;建筑类型;x;y;z;旋转;末列`。**第 4 列 y 是引擎直接使用的绝对高程**，heightmap 一改全表过期。

- 换算公式（原版反推，**不要改系数**）：`y = 0.09786518 * h + 0.259962`（海平面 h=95 → y≈9.56）。
- **行序绑定读法**：`np.frombuffer` 直读 BMP 存储序 → `row = z` **不翻转**；`PIL.Image` 读（已翻成视觉序）→ `row = H-1-z`。两种等价，**混搭必错**。自检：非浮港建筑必须接近 100% 落在陆地（h≥96），四组合取中位残差最小者。
- **采样用双线性**：整数采样残差劣化 10 倍（0.003→0.03），让"该不该改"的判定全线漂移。
- **mean|r| 与 median|r| 必须一起看**：一批从未初始化的行（y 全等 9.50，实测 3264 条）会把 mean 从 0.004 抬到 0.22，只信 mean 会得出"重算全表"的错误结论；只信 median 会漏掉脏行。
- `floating_harbor` 整类跳过（本该在水面）；越界保持原值；海上/近岸建筑钳到 `h≥94` 防掉水下。
- 容差 0.005 内不动——**不要为"格式统一"重写全表**，diff 必须只剩真要修的行。
- 验收基线：修后 `mean|r| ≤ 0.005`、`max|r| ≤ 0.3`。

**换行符陷阱**：用 Python 默认 `open()` 读，`\r\n` 被 universal-newlines 静默转成 `\n`，换行检测会把输出写成纯 LF（实测字节差 -40576）。**字节级保持原行尾**：按字节读、`split('\r\n')`、`'\r\n'.join` 写回，改完核对 CRLF 计数与逐行差异形态（只允许第 4 列变化）。

## §2 防穿模（贴地之后被山埋）

贴地把 y 对准了**采样点**，但模型有占地范围（footprint）：陡坡上**周围的坡面比基座高**，模型被埋。判据：y 精确等于采样换算值（贴地没错）而邻域地形明显更高。

**目标不是"贴着采样点"而是"footprint 内不被埋、又不悬空"**。三类建筑的正确处置完全不同：

| 建筑类别 | 处置 |
|---|---|
| naval 类（`dockyard`/`naval_*`/`coastal_bunker`）与 `floating_harbor` | **永不抬**——贴水面是对的，旁边山在岸上 |
| 7×7 邻域内海洋像素（h<90）占比 >25% 的陆地建筑 | **跳过**——悬崖脚下，抬到崖顶会悬空（实测差 11 个单位）；这是选址问题，只能挪位置 |
| 其余陆地建筑 | 邻域高度 **90 分位**（不是 max）高于当前 y 超过 1.0 → 抬到 90 分位 |

**失败版本记录（为什么是 90 分位 + 海占比这两道闸）**：

| 版本 | 规则 | 结果 |
|---|---|---|
| v1 | 9×9 max，阈值 0.2 | 抬 85%——地形处处有起伏，平地建筑全被抬 |
| v2 | 9×9 max，阈值 1.0，naval 除外 | 仍 52%——贴岸悬崖建筑被抬 11 单位悬空 |
| v3 | max 且差 >6 跳过 | 仍 52%——"邻域有高点"本来就普遍 |
| **v4** | **海占比>25% 跳过 + 90 分位、阈值 1.0** | **13%**，抬升量长尾正常（+1 占八成） |

判定标准："邻域 max 高"只说明附近有高地；**"邻域大部分地面高于基座"（90 分位超阈）才是真嵌进坡里**。90 分位而非 max，是给防悬空留 10% 余量。

**验收**：抬升占比应在 10~20% 量级（全图过半必是规则错了）；抬升量分布应长尾（+1 最多，+5 以上个位数）；naval/海岸类零改动。

## 工具（仓库根目录）

| 脚本 | 用途 |
|---|---|
| `fix_buildings_height.py` | 诊断/出力（**有 LF 陷阱**，只用于看报告） |
| `fix_height_crlf.py` | 高程重算落地（CRLF 保持版） |
| `fix_pierce.py` | 防穿模抬升（v4 规则） |

流程：heightmap 改动 → `fix_buildings_height.py --map <map目录>`（诊断）→ `fix_height_crlf.py`（落地）→ 游戏内看穿模 → `fix_pierce.py`（抬升）。

## 常见误判

- ❌ 行序记成绝对规则（"z 必须翻转"）——正确写法**绑定读法**，混搭才会错；先跑自检。
- ❌ 拿 buildings 的 x/z 去比 provinces.bmp 像素省号判定对错——**原版也是 0% 命中**；判断是否落地只看 y 与 heightmap 采样吻合度。（本 mod 的 buildings.txt 坐标恰与像素同系，但这是生成工具决定的，不能当通用假设。）
- ❌ 只看 mean|r| 判"全表重算"；只看 median|r| 漏掉 y=9.50 的脏行。
- ❌ `y≈9.5` 就判"未初始化"——近岸平地本来就该 9.5；要看 `y-(A*h+B)`。
- ❌ 把 `floating_harbor`/naval 类一起"扶正"——港口被拽上岸/悬空。
- ❌ 防穿模用"邻域 max"一把抬——实测 52~85% 被抬、悬崖建筑悬空 11 单位。
- ❌ 忘了 universal-newlines 的 LF 陷阱——diff 全文件污染。
- ❌ 改完不回读校验 CRLF 计数、行数、逐行差异形态。
