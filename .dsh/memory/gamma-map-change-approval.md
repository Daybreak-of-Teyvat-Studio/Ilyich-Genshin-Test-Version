**任何改变地块归属（转省、飞地并入、均分重划、州号重排）的操作，目标必须由用户明确指定**，不能用"地理上更合理"自行推断后直接写盘。

**Why**：用户给飞地指令时的格式一直是自己点明目标（`3659归入state68`、`3403和3423归入51`）。我自行把 5 处飞地按"紧邻州"迁移（3499→59、4686→530、2643→231、461→527、1154→544），被用户质问"具体执行你有问我了吗？你就做？"，最终**全部回滚**。用户对"均分"也有明确分歧点：`和周围的s均分` 有 A（只把飞地并入紧邻州，省数不变）/ B（与周围多州合并重划）两种做法，**必须让用户选**。

**How to apply**：
1. 收到模糊的改图指令 → 先只读侦察出**方案与影响面**（哪些州、哪些省、是否跨国家变更），把选项摆给用户，等他点目标。
2. 明确点名的指令（如 `188,3548+135`）可以直接执行；**没点名的一律不动**。
3. 动手前先干跑（`--dry`）把明细念一遍；每个写盘动作都要有可回滚的备份目录。
4. 用户点名的"空 state 编号重排"先确认他指的是哪些号——我全图扫到 `provinces` 为空的州 = 0 个，不能凭猜执行。
5. **例外（已获授权）**：大面积重划（如至冬涂色图）由用户提供明确设计图 → 可自动落地方案，但**落地后要主动报告歧义项**（双名取后、后缀位置、未涂省挂靠、落选名字）等用户裁决，不自行隐瞒或扩大解释。
6. **同一句短指令的语义先验证再动手**：`47+15` 我先查了 beta47「眠龙谷」/beta15「望风山地」都对不上，才回落到转省语义；用户后来明确"是正常的转省"。**问一次成本远低于做错返工**——但注意用户不喜欢反复确认，查证后仍不确定时，用最符合上下文（同国、目标州名与省 VP 名吻合）的解释并在报告里标出假设。
