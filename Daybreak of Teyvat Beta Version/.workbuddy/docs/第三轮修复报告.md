## 2. 本轮修复清单（35 处 / 7 个文件）

### 2.1 `common/ai_equipment/generic_tank.txt` —— 16 处（重要）

**症状**：老日志里 `common/ai_equipment/generic_tank.txt:667: has_tech: Invalid tech`，每行重复 **5,489 次**，16 行合计 **87,824 次**（占整个日志 74%）。

**根因**：这 16 行用 `has_tech = <陆战学说名>` 判定学说。1.19 把陆战学说从科技树移到了 `common/doctrines/`，必须改用 `has_doctrine`。而且 **`mobile_warfare` 和 `trench_warfare` 这两个 id 在 1.19 里根本不存在了**——不是简单换个键名就行。

**学说 id 映射依据**（不是我猜的，是从文件自身的命名矩阵反推 + 原版定义核对）：

文件里是标准的「四学说 × N 档」矩阵，块名前缀与学说一一对应：

| MOD 块名前缀 | MOD 原用 id | 1.19.3 正确 id | 依据 |
|---|---|---|---|
| `BLITZ_*` | `mobile_warfare` | **`new_mobile_warfare`** | 原版 `land_grand_doctrines.txt` 第 1 行的 id |
| `SUPERIOR_*` | `superior_firepower` | **`superior_firepower`** | 同上，第 120 行 |
| `TRENCH_*` | `trench_warfare` | **`grand_battleplan`** | 同上，第 254 行；`trench_warfare` 在原版全部目录中**零定义** |
| `SOVIET_*` | `mass_assault` | **`mass_assault`** | 同上，第 369 行 |

决定性佐证：第 875–885 行 `basic_medium_tank_default` 的 `enable` 写的是
`NOT = { OR = { 四个学说 } }`——即「四个学说一个都没选时用默认方案」，作者列的正是**四大陆战学说**，只是其中两个名字过期了。

**影响**：修复前 `BLITZ_*` / `TRENCH_*` 两组 AI 坦克设计**永远不会启用**（条件恒为假），且「四选一」判定恒为真，AI 无法按学说选择坦克设计。修复后这套矩阵才真正生效。

改动：16 行 `has_tech = X` → `has_doctrine = Y`，行尾留 `# FIXED:` 标记。

### 2.2 `common/units/Ilyich_Hero.txt` —— 4 处

**症状**：`Unexpected token: fire_range / shore_bombardment / evasion / port_capacity_usage`（×4）。

**根因**：这 4 个键在 1.19.3 里**引擎完全不认识**（脚本解析层就报错），因此**当前是失效的——写了等于没写**。对照原版：`common/` 全目录中这 4 个键出现 **0 次**；原版 `common/doctrines/_documentation.md` 与自带手册也把其中三个标为 **OBSOLETE**：

| 键 | 手册/原版说明 |
|---|---|
| `fire_range` | 手册明确标注 **OBSOLETE**；主炮射程由装备/模块决定 |
| `shore_bombardment` | 手册标注 **OBSOLETE**；「lg_attack 和 hg_attack 决定对岸炮击」 |
| `evasion` | 手册标注 **OBSOLETE**；「改由 naval_speed 参与计算」（`naval_speed = 28` 已在位） |
| `port_capacity_usage` | 原版零定义，引擎不识别 |

**处理方式**：**注释掉而非删除**（保留作者原意，可随时恢复）。因为这四个键当前本来就是失效的，所以**行为零变化**，纯粹消掉 4 条报错。

## 4. 还没动的（需你拍板）

### 4.1 唯一剩下的脚本报错——**不在本 MOD 里**

```
common/on_actions/Ilyich_Tech_on_actions.txt:33 / :41 / :49: root: Invalid Scope, provided: None   (×72)
```

这个文件属于**另一个 MOD**：`Ilyich Genshin Tech and Model/common/on_actions/Ilyich_Tech_on_actions.txt`（本 MOD 目录下没有这个文件）。

**诊断**：第 33/41/49 行都是 `limit = { ROOT = { has_full_control_of_state = PREV } }`。它位于 `on_startup → effect → every_country → random_owned_controlled_state` 内。`on_startup` 是全局 on_action、**没有国家根作用域**，所以 `ROOT` 在这里是 `None`（报错原文 `provided: None` 正是这个意思）。旁边的 `on_monthly_MOT` 写法正常，可作为参照。

**为什么我不直接改**：这是别人 MOD 的文件，且改法涉及设计意图（`random_owned_controlled_state` 本身就是「自己拥有且控制」的州，那个 `limit` 本就多余）。**你说改我就改**，方案是去掉冗余 `limit` 并把 `create_unit` 的 `owner = ROOT` 改为 `owner = PREV`。
